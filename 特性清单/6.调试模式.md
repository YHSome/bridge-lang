桥语言自带断点调试：命令行和编辑器两条路，行号都对着 `.bridge` 源码。

## 一、命令行

```bash
python 桥.py 调试 主.bridge --断点 4,9:合计>10
```

- `4`：第 4 行无条件停；
- `9:合计>10`：第 9 行**条件断点**，`合计 > 10` 为真才停；
- 没给断点就直接停在第 1 行，相当于"进来先看一眼"。

进去以后：

| 命令 | 作用 |
| --- | --- |
| `n` / 步入 | 执行下一行，进入函数 |
| `o` / 步过 | 执行下一行，不进入函数（整段函数当一步） |
| `c` / 继续 | 跑到下一个断点或结束 |
| `l` | 看当前行前后 3 行源码（`●` 标断点、`→` 标当前位置） |
| `p 变量` | 打印变量（`p 记录["书名"]` 也行） |
| `e 表达式` | 算一个表达式：`e len(数据库["借阅"])` |
| `w` | 列当前帧全部局部变量 |
| `b` | 看所有断点（带条件） |
| `q` | 退出 |

## 二、编辑器

| 操作 | 效果 |
| --- | --- |
| `F9` | 当前行打/取消断点（行底红条）；断点**按文件记忆**，切回来还在 |
| `Ctrl+F5` | 按断点运行，停在断点行，输出区下方「输入（回车发送）」可以敲调试命令 |
| 运行出错 | 出错那一行自动标红 + 下划线 |
| 保存 | 顺手编译一次，有语法错误只在状态栏提示，**不阻止保存** |

## 三、它怎么实现的（一句话）

`sys.settrace` 只跟踪"文件名等于被调试 `.bridge`"的帧，事件只认 `line`；
条件断点就是停下来前先 `eval(条件, 帧.f_globals, 帧.f_locals)`；
步过靠"帧深度不超过停下的深度"，所以函数调用会被当一步跨过去。
