桥语言独有的东西（`标记/跳转到`、`读取/新建文档`、JSON、表格、`运行/并行`）平时靠
"运行时名字注入"工作；编译成 `.py` 时这些名字得有个来源。两种编译方式：

## 一、默认：import 运行时

```bash
python 桥.py 编译 主.bridge -o 主.py
python 主.py
```

产物开头是：

```python
import sys as _桥sys; _桥sys.path.insert(0, '<桥语言根>')
from 转译器.运行时 import 桥跳转, 桥读取, 结构化, 文档  # 桥语言运行时
```

**要求**：跑产物的机器上有桥语言目录（`sys.path` 指向它）。适合"本机/同一批机器"。

## 二、自包含：把运行时内联进产物

```bash
python 桥.py 编译 主.bridge -o 主.py --自包含
```

产物会把 `转译器/运行时.py` 的源码（约 600 行）直接贴在开头，随后才是你的代码。
所以产物**不再需要** `from 转译器.运行时 import …`，只有两种情况还依赖桥语言：

- 程序里用了 `运行/并行`（它们要现场编译别的 `.bridge`，必须有转译器本体）；
- 程序里 `导入` 了自己项目里的其它 `.bridge` 模块（同样要转译器）。

## 三、什么时候用哪个

| 场景 | 选 |
| --- | --- |
| 自己机器上跑、图快 | 默认 |
| 发给同学/放服务器，不想让他们装桥语言 | `--自包含` |
| 要发布单个 exe | 先 `--自包含`，再 PyInstaller 打包（把 `转译器/运行时.py` 也带上） |

## 四、验证

```bash
python 桥.py 编译 示例/特性/JSON节点.bridge -o /tmp/x.py --自包含
grep "from 转译器.运行时" /tmp/x.py || echo 没有运行时 import 了
python /tmp/x.py
```

自检里也有一条：`自包含编译 + 正则/子进程/日期/表格`，会检查产物里没有
`from 转译器.运行时 import` 且能跑出正确输出。
